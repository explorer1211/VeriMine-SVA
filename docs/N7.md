# N7 验证、覆盖与闭环

N6 编译通过的属性在这里证明、判空洞、算覆盖，并把未触及的逻辑变成下一轮的挖掘目标。

```bash
verimine n7 cfg.yaml                          # 跑 N0–N6 和 N7
verimine n7 cfg.yaml --no-mutants             # 不做变异杀伤
verimine n7 cfg.yaml --loop 3                 # 覆盖驱动闭环，最多 3 轮
verimine n7 cfg.yaml --backend process        # 证明任务放到子进程（或 slurm）
verimine n7 cfg.yaml --dry-run --json
```

需要 `yosys`、`sby` 和一个 SMT 求解器；变异杀伤还要 Verilator。没有形式引擎时只做 S_val 离线检查，结果都是 `WEAK_EVIDENCE`，并给出提示。

## 步骤与代码位置

| 步骤 | 内容 | 代码 |
|---|---|---|
| 1 | 用 IR 在 S_val 上做离线检查，淘汰过拟合训练轨迹的候选（trace_overfit） | `n7/offline.py` |
| 2 | 前件 cover 的可达性；证明不可达 → `VACUOUS` | `n7/prove.py`（cover 走同一引擎） |
| 3 | 分层证明 L0 / L1 / L2 | `n7/prove.py` |
| 4 | `sim_status`、`formal_status`、`cover_status` 合成一个总状态 | `n7/status.py` |
| 5 | 按 COI 大小和重要性排序分配算力；超时标 `resource_limit` | `n7/coi.py`、`n7/prove.py` |
| 6 | Slurm 并行，结果落库 | `n7/sched.py`、`n7/jobs.py`、`n7/store.py` |
| 7 | 四项覆盖：COI、证明核、空泛性、可达性 | `n7/coverage.py`、`n7/reach.py` |
| 8 | 覆盖缺口清单 | `n7/coverage.py: gaps` |
| 9 | 覆盖率驱动闭环：缺口 → N4 → N5 → N6 → N7 | `n7/pipeline.py: run_n7` |
| 10 | 诚实标注 + 变异杀伤 | `n7/coverage.py`、`n7/mutation.py` |

## 总状态

| 状态 | 条件 |
|---|---|
| `ENV_ERROR` | N6 编译不过，或引擎读不了设计 |
| `FAILED` | 引擎找到反例；或非挖掘来源的候选在合法 S_val 轨迹上被违反（仿真反例） |
| `VACUOUS` | 前件 cover 被证明不可达：断言永远不会触发 |
| `REVIEW_REQUIRED` | 候选依赖合法性未知的轨迹（N3：不自动接受），或证明超时（`resource_limit`） |
| `PROVEN` | 全深度证明通过，且前件可达（或没有前件） |
| `BOUNDED` | 深度内无反例，归纳未收敛 |
| `WEAK_EVIDENCE` | 只有仿真证据；或前件在界内没被走到、也无法证明不可达（空洞性不能排除） |

`resource_limit` 不是七种状态之一：它记在 `formal_status` 里，并让总状态成为 `REVIEW_REQUIRED`（没做完不等于通过）。

## S_val 离线检查与 trace_overfit

N4 在 S_mine 上检查候选；N7 在 N3 切出来的 S_val 上再查一遍，用的是同一套 IR 语义：

- **合法轨迹（user / constrained）上被违反，且候选来自挖掘（路径 B）**：判 `trace_overfit`，不证明，状态 `REVIEW_REQUIRED`，反例写进报告。这是“只拟合了训练轨迹”的定义。
- **合法轨迹上被违反，但不是挖掘来源（模板、LLM）**：设计在合法轨迹上违反了它，是反例：直接 `FAILED`，不做形式证明。
- **只在合法性未知的轨迹上被违反**：输入可能非法，保留，交给形式证明；没有证明则 `WEAK_EVIDENCE`。
- **哪里都没被走到**：没有仿真证据，由形式结果决定。

## 分层证明

| 层 | 方法 | 对象 |
|---|---|---|
| L0 | 浅层 BMC（`n7_l0_depth`） | 全部断言、全部前件 cover、可达性 cover |
| L1 | k-induction 完整证明（`sby` prove） | L0 未定的断言中排名前 `3 × n7_l1_k` 条，以及 L0 未到达的 cover |
| L2 | 更深（`n7_l2_depth`）、更长超时（`n7_l2_timeout`） | 仍未定、排名前 `n7_l2_top` 条 |

排序：先按 COI 大小（便宜的先做），再按重要性（PageRank，`n7_use_pagerank`，FTO 敏感，默认关），最后按名字；合法性未知的排最后。每次证明只放这一层的属性，Yosys 的 `prep` 会按需保留逻辑。

超时由 sby 报告 `TIMEOUT`，对应的属性记 `resource_limit`，不算通过。

## 四项覆盖

| 指标 | 算法 | 说明 |
|---|---|---|
| COI 覆盖 | 逻辑块（每条赋值）落在至少一条 PROVEN 断言的影响锥里的比例 | 图由 N1 的赋值与父子连接构成（`n7/coi.py`），可直接计算 |
| 证明核覆盖 | 开源栈暂缺 | 能力矩阵 `proof_core: null`；报告写“缺”，同一栏给出变异杀伤的近似值并标注“近似” |
| 空泛性 | 前件 cover 被证明不可达的比例 | cover 结果；只算证明为不可达的，界内没走到的不算 |
| 可达性 | 分支、状态：轨迹（N3，S_val）与形式 cover 两套 | `n7/reach.py` 把分支 guard 和 FSM 状态交给引擎，最多 `n7_reach_max` 条；引擎证不可达的会在缺口清单里消掉 |

**诚实标注**（报告里也写着）：COI 覆盖只表示“被已证明断言的影响锥触及”，不等于验证充分。证明核覆盖拿不到，用变异杀伤补充，它是近似，不是证明核。

## 缺口与闭环

缺口 = 没有被任何 `PROVEN` 断言触及的逻辑块（按实例分组），加上轨迹没覆盖、形式 cover 也没解释成不可达的分支/状态。

`--loop R` 时：缺口信号写进 N4 的 gap 输入（`run_n4(extra_gaps=...)`），缺口区域获得更高配额，重新生成候选 → N5 → N6 → N7。停止条件：COI 覆盖达到 `n7_loop_target`、连续两轮提升低于 `n7_loop_epsilon`、或轮数用完。

## 变异杀伤

对建模实例里每条赋值所在的行做一次文本变异（`==`↔`!=`、`&&`↔`||`、`+`↔`-`、`&`↔`|`、`^`→`~^`），用 N5 同一组向量在 Verilator 里跑，任何 PROVEN 断言失败即“杀死”。最多 `n7_mutants` 个变异体；编译不过的不计入。变异体运行的检查器端口统一改成 `p_<信号>`（与 N6 第 1 轮相同），避免断言名与端口同名时 Verilator 拒绝。

## 并行与落库

`n7/jobs.py` 把一次引擎运行写成纯 JSON（文件、环境、属性、渲染方式），`n7/sched.py` 用三种方式执行：

- `thread`（默认）：本进程线程池；
- `process`：每个任务一个 Python 子进程；
- `slurm`：`sbatch --wait` 每个任务一个作业；没有 `sbatch` 时退回 `process` 并警告。**没有在集群上验证过**。

结果写 `verimine.db` 的 `n7_run`、`n7_prop` 表，按 N7 input_hash 存。

## 引擎抽象层

本阶段的映射：`load` = N6 的文件与 include；`prove` = L0/L1/L2；`get_cex` = 反例轨迹（`formal.trace`）；`get_cover_trace` = cover 到达的轨迹；`get_core` = 未实现（见证明核覆盖）；`vacuity` = 前件 cover 的不可达证明。

跨引擎一致率：报告给出交付版（Verilator）与验证版（Yosys）在 N5 差分测试上的状态一致率。商用引擎（JasperGold、VC Formal、Questa Formal、GalaxFV 等）仍是厂商文档/待确认，没有在本机跑过。

## 输出

- `runs/<run_hash>/n7.json`：状态、覆盖、缺口、轮次。
- `runs/<run_hash>/n7_report.md`：报告。
- 证明任务目录 `n7/<hash>/proof/L0|L1|L2`、变异 `n7/<hash>/mutation/`。

## 参数（`run.params`）

| 参数 | 默认 | 含义 |
|---|---|---|
| `n7_l0_depth` | 12 | L0 BMC 深度 |
| `n7_l1_k` | 8 | L1 取前 3×k 条，归纳深度 `n7_l1_depth`（默认 20） |
| `n7_l2_depth` / `n7_l2_timeout` / `n7_l2_top` | 64 / 300 / 8 | L2 |
| `n7_timeout` | 120 | L0/L1 每次 sby 超时（秒） |
| `n7_use_pagerank` | false | 重要性排序（FTO 敏感） |
| `n7_reach` / `n7_reach_max` | true / 64 | 形式可达性 cover |
| `n7_mutants` / `n7_mut_timeout` | 8 / 120 | 变异杀伤 |
| `n7_backend` / `n7_jobs` | thread / 1 | 并行方式 |
| `n7_loop_rounds` / `n7_loop_target` / `n7_loop_epsilon` | 0 / 0.9 / 0.01 | 闭环 |

## 提示代码

| 代码 | 含义 |
|---|---|
| `N7_TRACE_OVERFIT` | 挖掘来源的候选在合法 S_val 轨迹上被违反，已淘汰 |
| `N7_SIM_REFUTED` | 非挖掘来源的候选在合法 S_val 轨迹上被违反，作为反例 |

| `N7_MUTATION` | 变异体编译不过等 |

## 容量测试与能力声明

```bash
verimine capacity --tiers 1,2        # 档 1（约 500 行）、档 2（约 2 000 行）
verimine capacity --tiers all        # 1–4 档，10 000 和 75 000 行会跑很久
```

生成的测试设计是一个小模块的大量实例（无深层次、无存储器），每档记录 slang 与 Yosys 的读入耗时、峰值内存、浅层 BMC 能到多深、k-induction 能否证明。输出 `capacity_report.md` 与 `capacity.json`，其中“能力声明”给出本机验证到的大致行数，超出时的对策是 COI 裁剪 / 黑盒 / 拆模块。容量测试出来前不对外承诺规模。

这是生成的合成设计，读入耗时主要随实例数量增长；真实设计（深层次、存储器、接口）可能不同。

## 没做的

- 证明核覆盖：Yosys + SymbiYosys 能否给出证明核没有确认，报告里写“缺”，用变异杀伤近似。
- 跨引擎差分验证只覆盖两个开源实现（Verilator × Yosys）；规范要求的“至少两个引擎”中的商用引擎未接入。
- Slurm 后端没有在集群上验证。
- 行覆盖：RTL 没有插桩，用分支覆盖（赋值所在的 if/case）近似。
- COI 源级裁剪只做到“每条证明只放它那一层的属性 + Yosys prep 的按需保留”，没有实现跨实例的源级切片。
