# N6 编译检查

N5 渲染的两个版本各自过一遍编译器：交付版给 slang，验证版给 Yosys。编译不过的属性回到 N5 换更保守的写法重新渲染，最多 2 轮；仍不过的标 `ENV_ERROR`，写进报告，不进入 N7。

```bash
verimine n6 cfg.yaml                    # 跑 N0–N5 和 N6，写通过编译的交付版、验证版、报告
verimine n6 cfg.yaml --no-diff          # 重渲染的验证版不重做差分测试
verimine n6 cfg.yaml --dry-run --json
```

需要的工具：交付版检查只要 pyslang（已是依赖）；验证版检查要 `yosys`。没有 Yosys 时验证版不检查，原样保留 N5 的结果，并警告 `N6_LEG_SKIPPED`。

## 步骤与代码位置

| 步骤 | 内容 | 代码 |
|---|---|---|
| 1 | slang 编译交付版：设计 + 检查器模块 + bind 文件 | `n6/compile.py: slang_diags`，`n6/pipeline.py: _Delivery` |
| 2 | Yosys 读入验证版，插入方式与形式引擎相同（`endmodule` 前的 `include`，`read_verilog -formal`、`prep`） | `n6/compile.py: yosys_diags`，`n6/pipeline.py: _Verification` |
| 3 | 失败的回到 N5 重新渲染，最多 2 轮 | `n6/variants.py`，`n6/pipeline.py: run_n6` |
| 4 | 仍失败的标 `ENV_ERROR`，进入报告，不进入 N7 | 同上 |

## 诊断落到哪条属性上

两个工具都给出文件和行号。N6 自己写检查器文件和 include，所以知道每一行属于哪条属性：

- 落在属性所在行：算这条属性的。
- 落在检查器模块的公共行（端口表、`module`/`endmodule`）或 bind 语句：算这个检查器里所有属性的；如果消息里引用了其中某条属性的名字（slang：`redefinition of 'x'`），只算那一条。
- 落在设计文件、或没有位置（例如 Yosys 在 `hierarchy` 阶段报错）：二分查找。把属性分成两半分别编译，直到找出单独就会出错的属性（`n6_bisect_budget` 限制编译次数，默认 64）；如果只有放在一起才出错，剩下的每条都算。
- 设计本身就有的诊断不算：先单独编译一次设计作为基线。

Yosys 遇到第一个错误就停，所以验证版是循环读：找到出错的属性，拿掉，再读，直到干净。

## 哪些警告算错误

实测发现，有几类问题编译器只给警告，然后按错误的理解继续往下走。N6 把它们当作错误：

| 工具 | 诊断 | 不当错误会怎样 |
|---|---|---|
| Yosys | `Identifier ... is implicitly declared` | 不存在的名字变成一根没有驱动的自由线，证明照样进行，结论是针对这根线的 |
| Yosys | `Range select out of bounds` | 越界的位按 undef 读 |
| slang | `Redefinition`（断言名与端口同名） | Verilator 直接报错（`Block has the same name as port`），其他工具通常也报错 |
| slang | `IndexOOB` / `RangeOOB` | 越界选择 |

只看 N6 自己写的文件里的诊断。

## 重渲染

每一轮是同一个 IR 的更保守写法，意思不变，只换形式。交付版和验证版分开走：哪一路失败，哪一路才换写法。

| 轮 | 交付版 | 验证版 |
|---|---|---|
| 0 | N5 原样：每个实例一个检查器，端口与信号同名 | N5 原样：监视器，用 `$past` |
| 1 | 独立检查器：这条属性单独一个模块，端口改名 `p_<信号>`。断言名撞上信号名、或者别的属性弄坏了共用的端口，都不再影响它 | 展开：`$past(e, k)` 写成 k 层嵌套 `$past`，`$onehot`/`$onehot0` 写成 `$countones` |
| 2 | 无端口检查器：没有端口，bind 进实例后用向上层次名 `<模块>.<信号>` 读信号，没有端口类型和位宽可出错 | 显式历史寄存器：完全不用 `$past`，每个回看都是一个用 `$bits` 定宽、与属性同时钟的寄存器 `vm_h_<哈希>_<序号>` |

每一轮都把仍在的属性全部重新编译一遍，所以最后写出的文件就是最后一轮编译通过的那一份。某一路三轮都不过就淘汰这条属性，再编译一次确认剩下的仍然干净。

**实测例子**（`tests/test_n6.py::test_label_equal_to_a_signal_is_fixed_by_isolation`）：设计里有一个叫 `reset_value_st` 的信号，而 N5 给 `st` 的复位值断言起的名字也是 `reset_value_st`。两者在同一个检查器里，slang 报 `Redefinition`，另一条读这个信号的断言随之解析失败（`undeclared identifier`）。第 1 轮改成独立检查器、端口改名后通过。

**意思不变的证据**：验证版的两种重渲染写法都在 N5 的三方差分测试里跑过，所有属性的结果与 IR 一致（`test_verification_fallbacks_pass_the_differential_test`）。交付版的重渲染只改包装（模块、端口名、名字前缀），属性表达式本身不变。

**重做差分测试**：如果 N5 做了差分测试，而 N6 改了某条属性的验证版写法，就用同一个向量对这些属性再做一次（`n6_rediff`，默认开）。不一致的不进入 N7（`N6_REDIFF_MISMATCH`）。

## 状态

| 字段 | 含义 |
|---|---|
| `status` | `OK`，或 `ENV_ERROR`（它有的某一路三轮都没编译过） |
| `delivery_ok` / `verification_ok` | `true` 通过，`false` 失败，`null` 这一路不存在（N5 没能渲染，原因在 `n5_skip`）或没有检查 |
| `delivery_variant` / `verification_variant` | 最终用的写法（0、1、2，见上表） |
| `to_n7` | `status` 为 `OK`，并且差分测试（重做过的以重做结果为准）不是 `mismatch` |
| `history` | 每次失败：哪一轮、哪一路、当时的写法、诊断 |

N5 没能渲染的那一路不算失败：比如引用存储器的属性没有交付版，它照样可以 `OK` 并进入 N7，只走验证版。

## 输出

- `runs/<run_hash>/n6_sva.sv`、`n6_bind.sv`：通过 slang 编译的交付版，只含通过的属性。
- `runs/<run_hash>/n6_verification/vm_n6_<模块>.svh`：通过 Yosys 读入的验证版。标签是 `vm_n6_<序号>`，上一行注释写着对应的属性名（属性名本身可能与信号同名，Yosys 会拒绝，见下）。
- `runs/<run_hash>/n6.json`、`n6_report.md`：轮次、ENV_ERROR 及其诊断、重渲染后通过的属性。
- 数据库 `n6_run`、`n6_prop`，按 N6 input_hash 存。input_hash 包含 N5 的 input_hash 和 n5_hash、参数、N6 版本。

验证版的标签：Yosys 不允许即时断言的标签与信号同名（`Cannot add procedural assertion ... a signal with the same name`），所以 N6 和形式引擎都不用属性名作标签。N7 的引擎在渲染时代入自己的标签（`LABEL:` → `vm_<n>:`）；第 2 种写法的寄存器声明在检查之前，引擎按正则找标签，不再按位置。

## 参数（`run.params`）

| 参数 | 默认 | 含义 |
|---|---|---|
| `n6_rounds` | 2 | 重渲染轮数（0–2） |
| `n6_timeout` | 300 | 每次 Yosys 读入的超时（秒） |
| `n6_bisect_budget` | 64 | 二分查找最多编译几次 |
| `n6_rediff` | true | 重渲染的验证版重做差分测试 |

## 提示代码

| 代码 | 含义 |
|---|---|
| `N6_ENV_ERROR` | 有属性重渲染后仍编译不过 |
| `N6_LEG_SKIPPED` | 某一路没有检查（没有 Yosys、Yosys 读不了设计、pyslang 出错） |
| `N6_ENV` | 顶层环境（复位假设或用户 assume）Yosys 读不进去 |
| `N6_NO_REDIFF` / `N6_REDIFF_MISMATCH` | 重渲染的验证版没能重做差分测试 / 重做后不一致 |

## 没做的

- 交付版只用 slang 检查。客户用的商用工具可能更严格；能力矩阵里它们的条目仍是厂商文档（declared），没有在本机验证。
- 重做差分测试只针对验证版的写法变化。交付版的重渲染只改包装，表达式不变，所以不重做仿真。但差分测试的仿真一路用的是 N5 自己的包装：上面断言名撞信号名的例子里，N5 的仿真一路会编译失败（N5 报 `N5_DIFF_LEG`），这些属性在 N5 只有形式一路的比较结果。
