# N5 SVA 生成

把 N4 候选池里的每条候选渲染成两个版本，交给 N6 编译、N7 验证。

```bash
verimine n5 cfg.yaml                    # 跑 N0–N4 和 N5，写交付版、验证版、报告
verimine n5 cfg.yaml --no-diff          # 不做三方差分测试
verimine n5 cfg.yaml --dry-run --json
```

需要的工具：三方差分测试要 Verilator（交付版的并发 SVA 只有它能仿真）和 `yosys`、`sby`、一个 SMT 求解器。缺任何一个时只渲染、不做差分测试，并警告 `N5_NO_DIFF`。

## 步骤与代码位置

| 步骤 | 内容 | 代码 |
|---|---|---|
| 1 | 从 IR 渲染交付版（标准 SVA）和验证版（Yosys 能读的形式，不支持的写法降级成监视器） | `n5/render.py: props_of` |
| 2 | 统一生成时钟、`disable iff`（复位）、断言名 | 同上：`names` |
| 3 | 每条带前件的断言同时生成前件 cover | 同上 |
| 4 | 三方差分测试：IR 离线检查、仿真、形式验证，三者必须一致 | `n5/diff.py` |
| 5 | 渲染前读引擎能力矩阵，按矩阵降级，降级记录写进报告 | `verimine/engines.py`、`n5/render.py` |
| 6 | v5：标出每条属性所属的片段（有界延迟蕴含）和窗口长度 | `n5/render.py` |

## 两个版本

两个版本由同一棵表达式树渲染（沿用 N2b 的渲染器），所以检查的是同一件事；差分测试用来抓住不一致的地方。

**交付版**（`n5_sva.sv` + `n5_bind.sv`）：每个实例一个检查器模块，用 `bind <实例路径>` 挂上去。用户拿去任何工具里用的就是它。

```systemverilog
handshake_hold_out_valid: assert property (@(posedge clk) disable iff (!rst_n)
                                           (out_valid && !(out_ready)) |=> out_valid);
handshake_hold_out_valid_c: cover property (@(posedge clk) disable iff (!rst_n) (out_valid && !(out_ready)));
```

**验证版**（`n5_verification/vm_n5_<模块>.svh`）：Yosys 即时断言，插在模块的 `endmodule` 前，读入时加 `-formal`。

```systemverilog
always @(posedge clk) if (rst_n && vm_n2b_pv_clk && $past(rst_n))
  handshake_hold_out_valid: assert(!($past((out_valid && !(out_ready)))) || (out_valid));
```

**名字**：`<模板>_<后件信号>`，重名时加 `_2`、`_3`；前件 cover 是 `<名字>_c`。不变式（没有前件）不生成 cover，因为它的前件恒为真，没有空洞问题。

**时钟和复位**：时钟取自候选所在实例的时钟，`disable iff` 取该实例的复位（N2 沿端口连接追到的顶层复位）。复位值模板的前件就是复位有效，所以不带 `disable iff`。

## 能力矩阵与降级（第 5 步）

`verimine/engines.py` 列出每个引擎支持的写法：并发断言、`disable iff`、`|=>`、`$past`、`$past(e, k)`、通配比较、`inside`、生成块内信号、序列、活性、cover 动作、证明核、字级建模、增量证明。每个值是支持、不支持或未知（`None`），每个引擎标出依据：

| 依据 | 含义 | 引擎 |
|---|---|---|
| measured | 在本机用已装版本试过 | yosys-sby、verilator、icarus、slang（只填了试过的格，其余为未知） |
| declared | 厂商文档，本机未验证 | JasperGold、VC Formal、Questa Formal |
| pending | 接口待向厂商确认 | GalaxFV、Empyrean Formal MC、HimaFormal MC |

渲染前按属性用到的写法查矩阵：

- 引擎不支持、但有降级办法的，按办法降级并记录
- 不支持且没有降级办法的（例如生成块内信号对 Yosys），不生成验证版，原因写进报告
- 值为未知的，算作不支持

验证版（引擎 yosys-sby）的降级办法：

| 降级 | 做法 |
|---|---|
| monitor | 并发断言降级为监视器：`always @(时钟沿)` 里的即时断言 |
| gate | `disable iff` 降级为门控：复位无效时才检查；`\|=>` 还要求上一拍复位无效 |
| past | `\|=>` 降级为 `!$past(前件) \|\| 后件`，由 past-valid 寄存器门控 |
| mask | 通配比较降级为掩码比较 `(x & mask) == value` |
| or_chain | `inside` 降级为相等比较的或 |

报告里还列出每个引擎上有多少条可以直接用、多少条要降级、多少条不支持或未知。

## 三方差分测试（第 4 步）

同一个输入向量走三条路：

| 一路 | 做法 |
|---|---|
| IR | 用 Python 按采样值语义离线求值（`disable iff` 覆盖整个尝试：`\|=>` 的两拍都要复位无效） |
| 仿真 | 交付版在 Verilator 里跑，失败和 cover 命中由动作块打印出来（打印测试平台的拍计数，不打印 `$time`） |
| 形式 | 验证版在 SymbiYosys 里跑，所有输入用 assume 钉在向量上：BMC 给出每条断言第一次失败的拍，cover 模式给出每个 cover 第一次命中的拍 |

IR 求值两次，分别在仿真轨迹上和形式模型自己的轨迹上（在向量最后一拍放一个 cover，就能拿到形式模型走完整个向量的轨迹）。这样可以分开回答三个问题：

| 比较 | 不一致说明 |
|---|---|
| IR（仿真轨迹）与仿真的每一次失败、每一次命中 | 交付版渲染有语义错误 |
| IR（形式轨迹）与形式的首次失败、首次命中 | 验证版渲染有语义错误 |
| 仿真轨迹与形式轨迹上的设计信号 | Verilator 与 Yosys 对设计本身的理解不同（不是渲染问题，单独报 `N5_MODEL_MISMATCH`） |

前两项任一不一致，属性判 mismatch，警告 `N5_RENDER_MISMATCH`。这些属性不应进入 N7，N6 会把它们退回 N5 重新渲染。

**向量**：取 N3 的测试用例，最多 `n5_diff_cases` 个，每个截到 `n5_diff_cycles` 拍；每个用例前加 `n5_diff_reset_cycles` 拍复位，所以 `disable iff` 在向量中间也会被用到。用户轨迹优先，其次是受约束激励。

**检查器怎么挂上去**：Verilator 不接受 `bind` 到实例路径，所以测试平台直接例化检查器模块，用层次名连端口。bind 语句本身由 N6 的 slang 编译检查。

**为什么不比较全部失败拍**：BMC 每条断言只报第一次失败。仿真一路比较全部失败拍；形式一路比较首次失败拍。

### 差分测试发现并修正的问题

开发时差分测试找出了几处差别，都已修正：

- **验证版不检查第一拍。** N2b 的验证版一律加 `!$initstate`，但 SVA 第一个时钟沿就检查。对没有 `disable iff` 的属性（复位值的前件 cover），形式一路比 IR 晚一拍。N5 的验证版去掉了这个门控；带复位的属性在第一拍本来就处于复位中，不受影响。
- **只读 `$past` 不该延长复位门控。** `disable iff` 只覆盖一次尝试；不带 `|=>`、只读 `$past` 的属性不需要上一拍也在复位之外。N5 只对 `|=>` 加上一拍的复位条件。
- **对齐**（测试平台本身的问题，不是渲染）：Yosys 把时钟沿下的检查寄存一拍，报出的步数比所检查的值晚一拍；smtbmc 轨迹按"沿前采样"后第 0 行是第 0 步之前。两处都按一拍对齐。
- **异步复位在 0 时刻**（测试平台）：复位寄存器初值若直接是有效电平，Verilator 里没有边沿，异步复位不触发，而 Yosys 的模型里复位立即生效。测试平台让复位从无效电平开始，第一拍再拉有效。

N2b 的渲染不变（`verification` 的新参数默认保持原行为）。

## v5 片段（第 6 步）

N4 的 IR 只有三种形式：不变式、下一拍蕴含、带 `$past` 的数据传递，全部属于有界延迟蕴含片段。每条属性记 `fragment = bounded_implication` 和窗口长度（`$past` 的最大深度，加上 `|=>` 的一拍）。去重的可证明保证只在这个片段内成立（N9）。

## 哈希与落库

- **input_hash**（`tagged_hash("n5_input", …)`）：N4 的 input_hash 和 n4_hash、traces_hash、build_hash、env_hash（含 Verilator、yosys 版本）、参数、能力矩阵版本 `CAPS_VERSION`、`N5_VERSION`
- **n5_hash**：渲染结果（两个版本的文本）和差分测试的结论，不含轨迹和路径
- **表**：`n5_run`（计数、降级、差分测试概况）、`n5_prop`（每条属性的两个版本、降级、差分结论、明细）
- **文件**：`runs/<run_hash>/n5_sva.sv`、`n5_bind.sv`、`n5_verification/`、`n5.json`、`n5_report.md`；差分测试的工作目录在 `n5/<input_hash 前 16 位>/diff/`

## 参数（`run.params`）

| 参数 | 默认 | 含义 |
|---|---|---|
| `n5_diff` | true | 是否做三方差分测试 |
| `n5_diff_cases` / `n5_diff_cycles` / `n5_diff_reset_cycles` | 3 / 40 / 2 | 向量取几个用例、每个用例多少拍、用例前的复位拍数 |
| `n5_diff_timeout` | 300 | 仿真和形式各自的超时（秒） |

## 验证

`tests/test_n5.py`，样例沿用 `tests/golden/n4/`：

- **渲染**：两个版本的文本、名字去重、前件 cover、降级记录、窗口；没有复位的属性第一拍也检查
- **能力矩阵**：生成块内信号对 Yosys 不支持，于是只有交付版；每个引擎的矩阵字段齐全
- **交付版能被 slang 编译**（检查器模块加 bind 文件）
- **差分测试一致**：`src.sv` 打开路径 B 后 60 多条属性三方一致，其中有被向量抓到的错误候选，三路的失败拍相同；Verilator 与 Yosys 比较了几百个设计信号取值，没有不一致。fifo 示例（含子模块 `u_ctrl` 的检查器）也一致
- **差分测试能抓住渲染错误**：故意把交付版的 `|=>` 写成 `|->`，只有仿真一路不一致；故意去掉验证版的 `disable iff`，只有形式一路不一致
- **落库、确定性、命令行**

## 待定

- **多时钟设计不做差分测试。** 向量按单一时钟驱动
- **形式一路只比首次失败。** BMC 只报每条断言的第一次失败；要比全部失败拍，需要每条断言单独跑
- **向量来自 N3 的用例。** 错误的候选只有在向量碰到它时才会在三路里都失败；没碰到时三路都是"不失败"，一致但说明不了多少。报告里每条断言记了被尝试的次数（前件成立的拍数）
- **检查器不经过 bind 仿真。** Verilator 不支持 bind 到实例路径，bind 语句由 N6 的 slang 编译检查
- **能力矩阵里商业引擎和国产引擎的值没有在本机验证**，国产引擎全部为未知
- **PicoRV32、Ibex 还没跑**
