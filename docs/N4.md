# N4 候选挖掘

三条路径产出断言候选，合并到同一个候选池，交给 N5 渲染、N6 编译、N7 验证。

```bash
verimine n4 cfg.yaml                       # 跑 N0–N3 和 N4，写报告与候选表
verimine n4 cfg.yaml --dry-run --json      # 不写库，输出完整结果
verimine n4 cfg.yaml --audit-export a.json # 导出 LLM 调用审计日志
```

## 三条路径

| 路径 | 内容 | 默认 | 代码 |
|---|---|---|---|
| A 规则和模板 | 从 N2 的结构证据套模板，不需要轨迹 | 开 | `n4/templates.py` |
| B 决策树挖掘 | GoldMine 式：在 S_mine 上训练 CART，叶子转成蕴含式 | **关**（FTO 敏感，实验功能） | `n4/tree.py` |
| C LLM | 只给结构摘要，输出受 JSON schema 约束 | 关（`llm.mode`） | `n4/llm.py` |

LLM 关闭时路径 A 完整运行；路径 B 是否发布取决于 FTO 结论。

### 路径 A：模板

| 模板 | 结构证据 | 形式（例） |
|---|---|---|
| `reset_value` | 寄存器在复位分支被赋同一个常量 | `!rst_n \|=> st == 1` |
| `onehot` | 状态机（≥3 个状态）的所有编码都是单热码 | `(st & (st - 1)) == 0 && st != 0` |
| `fsm_encoding` | 状态机有未用编码（不是单热码时） | `st == 0 \|\| st == 1 \|\| st == 2` |
| `fsm_transition` | 可达状态 v 只能迁移到部分状态 | `st == 1 \|=> st == 1 \|\| st == 2` |
| `mutex` | 两个 1 位组合信号的驱动条件互相矛盾（`a = x`、`b = y && !x`；`a = s == 1`、`b = s == 2`） | `!(out_valid && waiting)` |
| `handshake_hold` | N2 接口事件 valid/ready、req/ack，本实例驱动 valid、接收 ready | `out_valid && !out_ready \|=> out_valid` |
| `handshake_data` | 同上；与 valid 同前缀的输出按命名认为是数据（弱证据） | `... \|=> out_data == $past(out_data)` |
| `counter_range` | N2 计数器与常量 K 比较，复位、装载值都不超过 K | `beats <= 9` |
| `fifo_flags` | N2 识别的 full / empty | `!(full && empty)` |
| `fifo_bound` | full 由占用计数 `>= K` / `== K` 得到 | `count <= 16` |
| `fifo_overflow` / `fifo_underflow` | push/full、pop/empty 加占用计数 | `full && push && !pop \|=> count == $past(count)` |

- **方向。** 握手保持只在本实例驱动 valid 时生成：这是它的义务，属于断言。对方驱动 valid 时是环境假设，归 N3a。
- **模板只提议，不判定。** 例如计数器和 5 比较却会数到 15，`hits <= 5` 照样提出来。在合法轨迹上被违反的，下面的 S_mine 检查会淘汰；没有轨迹时交给 N7 判 FAILED。
- **时钟。** 模板都带时钟（`disable iff` 也需要）。实例的时钟不唯一或找不到时跳过，并警告 `N4_NO_CLOCK`。
- **复位值。** 前件就是复位有效，所以不带 `disable iff`。

### 路径 B：决策树（实验功能）

GoldMine 式决策树挖掘在 FTO 起点清单里（US9021409B2）。代码里标为 FTO 敏感，默认关闭；用 `run.params.n4_path_b: true` 打开，打开时警告 `N4_PATH_B_EXPERIMENTAL`。

1. **目标：** 每个 1 位输出端口、1 位寄存器，以及每个 N2 状态机的每个状态（`st == v`）。每个目标在 S_mine 上建一个数据集
2. **特征：** 只取 N2 中该目标的 COI 内、同一实例里的 1 位信号和状态谓词，按时延 0 到 k 展开（`n4_tree_window`）。寄存器目标只用时延 ≥1 的特征，因为它由上一拍决定；目标自身只以时延 ≥1 出现
3. **训练：** CART（Gini），限制深度（`n4_tree_depth`）和叶子最少行数（`n4_tree_min_leaf`）；只用所有特征都已知的行
4. **叶子转蕴含式：** 纯叶子的路径条件作前件，叶子取值作后件。条件全来自上一拍时，整体平移一拍：`$past(a) && $past(b) |-> t` 写成 `a && b |=> t`
5. **限额：** 每个目标最多 `n4_tree_max_per_target` 条，按叶子支持数从大到小取

候选的轨迹合法性取训练轨迹里最差的一类。决策树是在 S_mine 上训练的，所以 S_mine 驳不倒它；`src.sv` 上路径 B 有几条只是 BOUNDED 或 FAILED，要靠 N7（S_val 检查和形式验证）判断。

### 路径 C：LLM（可选）

1. **输入只给结构摘要（L2）：** 模块的端口、VDG 邻域、状态图、角色表，不给源文件
2. **信号名脱敏（L1）：** 端口写成 `p0, p1, …`，内部信号写成 `s0, …`。映射表只在本地，回答再映射回真名
3. **输出受 JSON schema 约束**（`llm.OUTPUT_SCHEMA`）：
   - 模板实例：`mutex`、`onehot`、`handshake_hold`、`implies`
   - 或者命题：用表达式树给出前件、后件，可选 `next`；运算符限定在白名单内
   - 不接受 SVA 文本。整份回答不是 JSON 就整份丢弃；单项不合 schema，或引用了摘要中没有的信号，就丢弃该项并警告 `N4_LLM_REJECTED`
4. **提示要求**只提与实现无关、可观察的性质（`llm.SYSTEM`）
5. **不直接信任：** LLM 的候选与 A、B 一样进候选池，经过 S_mine 检查，再交给 N6、N7

**调用方式**（按模块调用一次，同一模块的各实例共用回答）：

| provider | 说明 |
|---|---|
| `openai`（或 `vllm`） | OpenAI 兼容接口：地址 `VERIMINE_LLM_URL`，密钥 `VERIMINE_LLM_KEY`。私有部署的 vLLM、国内云端都走这条 |
| `replay` | 从本地 JSON 文件读回答（`VERIMINE_LLM_REPLAY`，格式 `{"模块名": 回答}`），用于测试和离线复核 |

- 地址看起来是境外云端（openai.com、anthropic.com 等）时默认拒绝调用，并警告 `N4_LLM_FAILED`，需要显式设置 `run.params.n4_llm_allow_foreign: true`
- 调用失败只跳过路径 C，不影响路径 A
- **审计日志：** 每次调用写入 `n4_llm_audit` 表，包括输入摘要的哈希、回答原文、数据级别、被采纳的候选编号。这张表不是派生数据，schema 变化时不删。可以用 `--audit-export` 导出

## 合并候选池

代码在 `n4/ir.py` 和 `n4/pool.py`。

1. **统一 IR：** 前件、后件、时延（`|->` 为 0，`|=>` 为 1）、类型、来源、使用的特征。表达式是 N1 的表达式树，加上 `$past` 节点，和 N2b 相同，N5 可以直接渲染两个版本
2. **规范化后去重：** `canon` 把嵌套的 `&&` / `||` / `&` / `|` 拍平，交换律运算的操作数排序，去掉双重否定。同一实例内规范形式相同的候选算一条，来源合并（例如 A 和 C 都提出了 valid 保持，记为 `A+C`）
3. **三个标记**（规格要求每条候选都带）：
   - **来源：** A / B / C，可以多个
   - **轨迹合法性：** `none`（不依赖轨迹：模板、LLM）、`user`、`constrained`、`unknown`。来自 `unknown` 轨迹的候选默认降权，标 REVIEW_REQUIRED，不进入自动接受
   - **所依赖的假设：** 配置里的哪些 assume 涉及这条候选的信号 COI 内的顶层输入。复位值候选不依赖假设，因为复位期间输入不起作用
4. **S_mine 检查：** 每条候选都在 S_mine 上逐拍核对（复位期间不算）：
   - 在合法轨迹（`user`、`constrained`）上被违反：判 DROPPED，写明首次违反的位置
   - 只在 `unknown` 轨迹上被违反：保留，加一条证据说明，警告 `N4_UNKNOWN_VIOLATIONS`
5. **候选预算由覆盖缺口驱动：**
   - 按区域分配配额。区域是"实例 + 后件里的信号"
   - 每个区域 `n4_quota` 条；后件或前件触及覆盖缺口的区域乘以 `n4_gap_boost`
   - 超出配额的判 DEFERRED（暂缓，不删除）；总数超过 `n4_max_candidates` 时，先保留缺口区域的候选
   - 缺口目前来自 N3 的覆盖缺口清单：未走到的分支所赋值的信号和条件信号、有未访问状态或迁移的状态寄存器。N7 建好后改用它报出的缺口
   - 区域内的排序：非 REVIEW_REQUIRED 优先，然后依次比较来源（A、B、C）、轨迹合法性、S_mine 支持数、长度
   - 重要性（PageRank）只在打开 `n4_use_pagerank` 时作为并列时的辅助。它也是 FTO 敏感功能，打开时会警告

## 状态

| 状态 | 含义 |
|---|---|
| POOL | 进入候选池，交给 N5 |
| DEFERRED | 超出配额，暂缓 |
| DROPPED | 在合法轨迹上被违反 |

## 哈希与落库

- **input_hash** 由以下各项求哈希得到（`tagged_hash("n4_input", …)`）：
  - N3 的 input_hash 和 traces_hash、N2 的 n2_hash、build_hash
  - 参数（包括两个 FTO 开关）
  - LLM 配置（关闭时只记 `off`）、提示词集版本 `PROMPT_SET_VERSION`
  - `N4_VERSION`
- **n4_hash** 由候选表求哈希得到
- **表：**
  - `n4_run`：计数、各路径情况、预算
  - `n4_cand`：候选，记录 id、作用域、类型、文本、来源、轨迹合法性、依赖的假设、层级、状态、IR、明细
  - `n4_llm_audit`：LLM 审计日志
- **文件：** `runs/<run_hash>/n4.json`、`n4_report.md`

## 参数（`run.params`）

| 参数 | 默认 | 含义 |
|---|---|---|
| `n4_path_b` | false | 打开路径 B（FTO 敏感，实验功能） |
| `n4_use_pagerank` | false | 用 PageRank 作并列时的辅助排序（FTO 敏感） |
| `n4_tree_window` / `n4_tree_depth` / `n4_tree_min_leaf` | 2 / 3 / 3 | 决策树特征的时延窗口、树深、叶子最少行数 |
| `n4_tree_max_per_target` | 8 | 每个目标的候选数上限 |
| `n4_quota` / `n4_gap_boost` / `n4_max_candidates` | 8 / 3 / 2000 | 每区域配额、缺口区域倍数、候选总数上限 |
| `n4_llm_allow_foreign` / `n4_llm_timeout` | false / 120 | 允许境外云端、调用超时（秒） |

## 验证

`tests/test_n4.py`，样例在 `tests/golden/n4/`：

- **路径 A：** `src.sv` 上 7 类模板都生成了（单热、迁移、握手保持与数据、互斥、计数器范围、复位值）。故意写错的 `hits <= 5` 被用户轨迹淘汰；其余入池的候选全部被形式引擎证明（PROVEN）
- **fifo 示例：** FIFO 类模板都生成了；依赖假设的标记正确（`count <= 16` 依赖 `no_push_when_full`，复位值不依赖）
- **路径 B：** 默认关闭；打开后从状态谓词挖出 `st == 2 |-> out_valid`，从上一拍挖出 `out_ready && st == 1 && go |=> st == 2`，都被证明；每个目标不超过上限；也有挖错的，说明 S_mine 驳不倒决策树，需要 N7
- **路径 C：** 用 replay 回答测试：
  - 发出的内容里没有真实信号名，也没有源码
  - 不合 schema 的项被丢弃
  - A 与 C 提出的同一性质合并为一条
  - 审计日志写入并可导出
  - 境外地址默认拒绝，且不影响路径 A
- **候选池：** 规范化去重、缺口区域配额加倍、落库和确定性（两次运行 input_hash、n4_hash、编号都一致）

## 待定

- **路径 A 的计数器范围只看比较常量的最大值。** 只在比较中出现、却并非上界的常量（例如与 5 比较但会数到 15），由 S_mine 或 N7 淘汰，路径 A 本身不判断
- **路径 B 的特征只有 1 位信号和状态谓词。** 多位数据的比较（`x == k`、`x > k`）没有做；特征只在目标所在的实例内
- **路径 B 的替代方案没做。** 规格里的备选（模板加语法引导综合、基于证明的不变量）留到 FTO 结论之后
- **预算的缺口来自 N3，不是 N7。** N7 的覆盖缺口清单建好后替换；"最多 R 轮的覆盖闭环"也在 N7 接上
- **LLM 只有 OpenAI 兼容接口和 replay。** 国内云端的专有接口需要时再加；LLM 合规模式的法规要求没有核对，需法务确认
- **PicoRV32、Ibex 还没跑**
