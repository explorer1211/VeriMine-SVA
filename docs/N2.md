# N2 行为建模

输入：N1 的结构索引（`index_hash`）。
输出：变量依赖图 VDG、状态机及迁移图、计数器/移位寄存器/存储器候选、接口事件、信号角色表（带置信度）、PageRank、每个断言目标的 COI 和 COI 指纹、抽象层级标签。

```bash
verimine n2 examples/fifo/verimine.yaml            # 先跑 N0、N1，再建模并落库
verimine n2 examples/fifo/verimine.yaml --dry-run  # 只跑不写库
verimine n2 examples/fifo/verimine.yaml --json     # 完整模型 JSON
```

fifo 示例的输出：`u_ctrl.count`（加减计数器）、`waddr`/`raddr`（地址计数器）、`u_mem.mem`（存储器，写地址 waddr、读地址 raddr），以及 push/full、pop/empty 两对接口事件。

## 对 N1 的补充（索引 schema v2）

N2 需要的“赋值”表在 N1 规格里有（左值、右值引用的信号、控制条件栈、阻塞或非阻塞、位置），但 N1 初版只做了驱动关系。这次补进了 N1，而不是在 N2 里再跑一遍 slang，这样 N2 的输入就只有 `index_hash`：

- `n1_assign`：每条赋值的左值、右值表达式树、读取的信号、控制条件栈（外层 if 的条件和取真/取假分支、case 的选择表达式和分支项）、阻塞/非阻塞、位置
- `n1_connection`：每个实例的端口在父模块里接的表达式
- 端口和信号补上位宽、有无符号；信号补上非压缩维度（存储器候选）和所在 generate 块
- generate 块里的子实例现在也会遍历（初版漏了），generate 里的信号按 `g[0].t` 这样的相对路径命名，不会互相覆盖
- 所有位置都存相对 root 的路径；`index_hash` 不含源码位置，只改注释、空行不会让它变
- Yosys 不支持 `module m import pkg::*; (` 这种模块头里的 import，现在送给 Yosys 前把 import 挪到同一行的 `module` 前面（行号不变，诊断里的路径映射回原文件）。fifo 示例因此由 BLOCKED 变成 OK

表达式树的格式：`{"ref": "cnt"}` 是信号；`{"const": 1, "text": "4'd1"}` 是能折成常量的一切（字面量、参数、枚举值、常量表达式）；`{"op": "+", "args": [...]}` 是运算、选择、拼接、`?:`；`{"op": "opaque", "refs": [...]}` 是其余情况，只保留读取的信号。

旧数据库里的 n1_* 表（schema v1）会被自动删除重建：索引是派生数据，重建比迁移简单可靠。

## VDG

| 属性 | 取值 |
|---|---|
| 节点 `kind` | input / output / inout / reg（在时序块里赋值）/ wire / memory（带非压缩维度） |
| 节点 `level` | port（本实例的端口）/ internal（寄存器和中间线网） |
| 边 `kind` | data：u 在右值里（含左值的下标，如 `mem[addr]` 的 addr）；control：u 在控制条件栈里 |
| 边 `delay` | 1：v 在 always_ff 或带边沿事件的 always 里赋值；否则 0 |
| 边 `via` | assign（模块内）/ port（经端口连接跨实例） |
| 边 `reset` | 源是复位信号 |

时钟不作为边（它是事件，不是被读取的值）。复位信号来自配置和敏感列表里的异步复位，沿端口直连向下追踪到子模块。N1 判为 BLOCKED 的实例不建模（警告 `N2_SKIPPED_BLOCKED`），它在父模块里的输出就是无驱动的；CONTAINS_BLOCKED 的父模块照常建模。

## 结构识别规则

全部看 N1 的赋值树，不看名字：

| 结构 | 规则 | 置信度 |
|---|---|---|
| 计数器 | 寄存器 r 有一条 `r <= r ± …`，其余项都是常量或 1 位量（如 fifo 的 `count + (push && !full) - (pop && !empty)`）。报告方向（up/down/up_down）、复位值、装载值、与哪些常量比较 | 高 |
| 移位寄存器 | `r <= {r[6:0], x}`、`{x, r[7:1]}`、`r << k`、`r >> k`（LFSR 也算）。报告方向和串行输入 | 高 |
| 存储器 | 带非压缩维度的信号。报告写地址、写数据、读地址、是否时序写 | 有写入为高，否则中 |
| 状态寄存器 | 时序寄存器 s，不是上面几类；它的每个下一值都是常量、保持（s 自身），或一个组合信号 ns，而 ns 的每个值也都是常量或保持；s 作为 case 的选择表达式，或与常量比较；至少两个不同取值；不是 case 选择表达式时位宽 ≥ 2 | case 为高，只有比较为中 |

“每个下一值都是常量或保持”这一条把数据寄存器排除在外：`data_q <= din` 后面再拿 `data_q == 8'hff` 比较，不会被当成状态机。1 位标志一般也不当状态机，除非它被 case。

**迁移图**：对每条给 s（或 ns）赋常量的语句，源状态从控制条件栈读出：case(s) 的分支项、`default` 分支（所有未列出的状态）、`if (s == C)` 或 `if (s != C)` 的 else 分支；读不出来就是“任意状态”。迁移条件是栈里其余的条件（去掉针对状态本身和复位的条件）。复位分支给出的值是复位状态，不算迁移。还有两条规则：

- 同一个块里后面一条没有附加条件的赋值会覆盖前面的：`nxt = state;` 之后 `REQ: nxt = WAIT;`，REQ 就不会自环。
- 单进程状态机里寄存器在没被赋值的路径上保持原值；这类自环标 `implicit: true`、条件写“无赋值时保持”。是否真有这条路径需要求解条件，留给 N2b/N7 确认。

报告 `reachable`：从复位状态沿迁移可达的状态，供 N2b 查不可达状态。

## 接口事件

名字只用来提出配对（同前缀 + valid/ready、req/ack、push/pop、full/empty 及常见变体，如 `wr_en`、`rdy`、`gnt`），置信度由结构决定：

| 置信度 | 依据 |
|---|---|
| 高 | 两个信号在同一表达式或同一条件里一起使用（`valid && ready`、`push && !full`，包括子模块端口连接上的表达式） |
| 中 | 端口方向相反（一个输入一个输出） |
| 低 | 只有命名 |

## 信号角色表

每个角色带 `confidence`（高/中/低）和 `evidence_kind`：

- `structural`：结构证据，强
- `trace`：轨迹证据，强（N3 之后补充，目前没有）
- `naming`：只有名字像，弱，置信度固定为“低”。结构已经给出同一角色时不再另列命名证据

角色：clock、reset、state_register、next_state、counter、shift_register、memory、valid、ready、req、ack、push、pop、full、empty。

验收口径（`test_golden_set_recognition_rate`）只计 structural 且置信度为高或中的角色。

## PageRank

在 VDG 上做幂迭代（阻尼 0.85），排名从读取者流向被读取者，所以被很多信号依赖的信号得分高。来自复位的边不参与：复位几乎控制所有寄存器，会压过其他信号又不说明行为。按排序后的节点做迭代、结果取 10 位小数，保证每次一样。按规格，它只是 N4 选特征时的可选特征，FTO 结论出来之前 N9 不把它作为默认排序主轴。

## COI 与 COI 指纹

断言目标：每个建模实例的输出端口、寄存器和存储器（时钟除外）。COI 是在 VDG 上反向可达的全部节点（data 和 control 边，跨周期），同时报告其中的顶层输入和时序深度。

COI 指纹 = `tagged_hash("coi", {target, 节点（含类型、位宽）, 锥内的边, 驱动锥内每个节点的逻辑})`，“逻辑”是赋值树及其控制条件栈、端口连接表达式。验收（`test_coi_fingerprint_tracks_only_its_cone`）：改一个锥里的逻辑，这个锥的指纹变，另一个锥的不变；只改注释，都不变。

没有用 N1 的模块指纹：它包含所有子模块指纹，子模块一改，父模块里与它无关的锥也会变，增量运行就失去意义。

## 哈希与落库

- `input_hash = tagged_hash("n2_input", {index_hash, clocks, resets, n2_version})`：N2 读的就是这些。`n2_version` 在识别规则变化时递增，旧模型不会被当成当前结果
- `n2_hash = tagged_hash("n2_model", 规范化的模型)`；同一输入跑两次两个哈希都一样（`test_hashes_deterministic`）
- 表（与 N0/N1 同库）：`n2_model`（主键 input_hash，记 build_hash、index_hash、n2_hash）、`n2_node`（含 PageRank、层级）、`n2_edge`、`n2_role`、`n2_fsm`、`n2_pattern`、`n2_event`、`n2_coi`。同一 input_hash 重跑不新增记录；schema 版本变化时 n2_* 表删除重建
- 完整结果写到 `runs/<run_hash>/n2.json`

## 验收

规格要求 golden 集上状态寄存器、计数器、握手信号识别正确率 ≥ 90%。`tests/golden/n2/` 是自建的 golden 集：

| 文件 | 内容 |
|---|---|
| `fsm_case.sv` | 双进程状态机：枚举、组合下一状态、case |
| `fsm_if.sv` | 单进程状态机：localparam 编码、if/else 比较，附带超时计数器 |
| `counters.sv` | 带回绕、可装载递减、加减、自由运行四种计数器 |
| `shifters.sv` | 左移、右移、`<<`、LFSR |
| `handshake.sv` | valid/ready 寄存器片、req/ack 请求方 |
| `negatives.sv` | 反例：被比较的数据寄存器、累加器、延迟链、名字像状态的信号、1 位标志 |
| `expected.json` | 27 条标注（含 9 条反例）+ fifo 示例 9 条 |

当前结果：27/27、fifo 9/9。测试设为“≥ 90% 且无错例”，规则改动造成的回退会直接暴露，而不是被 90% 吸收。

## 待定

- golden 集是自建的，规模小。规格的出口标准要求在 PicoRV32、Ibex 上跑通，需要下载这些项目并人工标注，用来校准误报。
- 状态机只识别“值都是常量”的写法；`state <= state + 1` 这类用算术编码的状态机会被当成计数器，独热码按位赋值（`state[IDLE] <= 1`）目前识别不了。
- 迁移条件只做文本化，没有化简，也不判断条件是否可满足；隐式保持自环需 N2b/N7 确认。
- 接口事件只在同一实例内配对；跨实例（valid 在父模块、ready 在子模块）的握手没有配对。
- 角色表里的 `trace` 证据要等 N3 有轨迹之后才有。
