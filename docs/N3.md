# N3 轨迹准备

为 N4 的挖掘和 N7 的离线检查准备数据。

- 输入：N2 的模型，以及配置里的 `waveforms`、`testbench`、`assumes`。
- 输出：
  - 按测试用例切好的轨迹，每个用例都标明来源、合法性，以及属于挖掘集 S_mine 还是验证集 S_val
  - 覆盖统计、缺口清单、质量判定
  - `n3.json` 和 `n3_report.md`
  - 每个用例的采样表（`traces/<case hash>.json.gz`）

```bash
verimine n3 examples/fifo/verimine.yaml              # 先跑 N0–N2，再准备轨迹
verimine n3 examples/fifo/verimine.yaml --explore    # 用户轨迹也做形式探索补缺口
verimine n3 examples/fifo/verimine.yaml --auto       # 用户轨迹之外再加自动激励
verimine n3 examples/fifo/verimine.yaml --fresh --dry-run --json
```

需要的工具：

- 仿真器：Icarus Verilog（默认）或 Verilator
- 形式探索：`yosys`、`sby` 和一个 SMT 求解器（与 N2b 相同）
- 读波形：wellen（`pip install pywellen`，或安装 `verimine[waves]`）。没装时使用内置的 VCD 读取器，此时不支持 FST

## 步骤与代码位置

| 步骤 | 内容 | 代码 |
|---|---|---|
| 1 | 轨迹来源按优先级取：用户波形 → 用户 testbench → 自动激励 | `n3/pipeline.py: run_n3` |
| 2 | 自动激励：随机仿真；形式探索（覆盖缺口转成 cover，用模型检查生成轨迹） | `n3/stim.py`、`n3/explore.py` |
| 3 | 用 wellen 读波形，信号名映射到 N1 的层级路径 | `n3/wave.py`、`n3/sample.py: find_scope, wave_names` |
| 4 | 裁剪：复位期、X 态、初始化阶段 | `n3/sample.py: cut` |
| 5 | 按测试用例切分，分成 S_mine / S_val | `n3/sample.py: make_cases`、`n3/pipeline.py: _split` |
| 6 | 覆盖统计：分支、状态、状态迁移、信号翻转；输出缺口清单 | `n3/cover.py` |
| 7 | 质量判定：覆盖低于阈值时提示补激励或启用形式探索 | `n3/pipeline.py: _finish` |
| 8 | 落库，记录轨迹 hash | `n3/store.py` |
| 9 | 激励合法性：自动激励必须满足已确认的假设 | `n3/stim.py: assume_constraints`、`n3/explore.py` |
| 10 | 没有假设时只生成保守激励，标记 `trace_legality = unknown` | `n3/pipeline.py` |

## 轨迹来源

| 来源 | 什么时候用 | 合法性 |
|---|---|---|
| 用户波形 `waveforms` | 配置了就用；VCD 或 FST | `user` |
| 用户 testbench `testbench` | 没有波形时用 | `user` |
| 随机仿真 | 前两者都没有（或加了 `--auto`），并且有已确认的假设 | `constrained` |
| 形式探索 | 跟随随机仿真自动开启；用户轨迹要加 `--explore` 才做 | `constrained` |
| 保守激励：复位后空闲、单点翻转 | 没有可用的假设 | `unknown` |

**用户 testbench。** N3 生成一个外层模块 `vm_n3_root`，在里面实例化 testbench 的顶层并加上 `$dumpvars`，不改 testbench 本身。每个 `runs` 项各仿真一次，参数是它的 plusargs。testbench 必须自己调用 `$finish`。

```yaml
testbench:
  files: [tb/tb_fifo.sv]
  top: tb_fifo
  dut: tb_fifo.u_dut          # 可选；不填时从波形里找设计顶层
  simulator: auto             # auto | icarus | verilator
  runs:
    - {name: smoke, args: []}
    - {name: fill,  args: ["+test=1"]}
```

**生成的 testbench（`vm_n3_tb`）。** 它实例化设计顶层，负责驱动时钟和复位：复位先保持有效 3 拍再撤销。数据输入的变化放在非有效沿之后，并在有效沿之前稳定，所以有效沿采样到的正好是设计消耗的值。

随机数来自自带的 xorshift 发生器，不用 `$urandom`。因此同一个种子在 Icarus 和 Verilator 上给出完全相同的激励。实测两边的轨迹只有一处差别：未初始化的存储器在 Icarus 里是 X，在 Verilator（二值）里是 0。所以默认用 Icarus。

**激励合法性（第 9、10 步）：**

- **随机仿真**用拒绝采样满足假设。每拍抽一组输入，检查所有假设，违反就重抽，最多 64 次；仍抽不到时仿真在这一拍结束，并给出警告 `N3_REJECTION_STUCK`。
  - 能检查的假设写法有三种：纯表达式、`a |-> b`、`a |=> b`（`|=>` 用一个寄存器记住上一拍的前件）
  - 支持 `$past(e)`、`$past(e, k)`（寄存器链，在有效沿采样），以及 `$stable` / `$changed` / `$rose` / `$fell`（先改写成 `$past`，见 `verimine/sva_text.py`）
  - 含序列运算（`##`、`[*]` 等）或 `$sampled` 的假设在 testbench 里无法保证，这时不做随机仿真，改用保守激励
- **形式探索**把假设直接加进模型，同时加入"第一拍复位有效"。有假设无法加入模型时跳过形式探索。
- **没有假设**时只生成保守激励：
  - 一个用例：复位后所有输入为 0
  - 每个输入位一个用例：复位后把这一位拉高 4 拍，最多 32 位
  - 这些用例都标 `unknown`；N4 从这类轨迹挖出的候选要降权，并进入 REVIEW_REQUIRED
  - 如果设计的输入确实可以取任意值，在配置里写一条恒真的假设（`{name: any_input, expr: "1"}`）即可放开随机仿真

**形式探索。** 目标有三类：随机仿真后仍未执行的分支、未到达的状态、未出现的 N2 迁移。每个目标转成一条 cover，交给 N2b 的引擎。

- 每条到达的 cover 产生一个新用例
- 证明不可达的目标从缺口清单移到"已证明不可达"，不再计入覆盖率的分母
- 进出不可达状态的迁移同样处理

## 采样、裁剪与切分

**名字映射。** 先在波形里找设计顶层所在的作用域，选变量与顶层端口、子实例、顶层内部信号同名最多的那个。内部信号也要算：testbench 的连线通常与端口同名，只看端口分不清 testbench 和设计本身（只看端口时，会选到 testbench 那一层，内部寄存器就采不到；N4 修正，`N3_VERSION = 3`）。然后按 N1 的实例相对路径一一对应：

- 转义标识符（`\u_dut `）会被规范化
- 写成 `g(0)` 的 generate 块名改成 `g[0]`
- 存储器（非压缩数组）不采样

`sources[].mapped / nodes` 记录对上了多少个信号。

**采样。** 每个有效时钟沿采一行，取的是这个沿之前的值，与 SVA 的采样语义一致。smtbmc 的形式轨迹在每一步开始的那个沿上显示该步的值，最后一步后面没有沿，所以会额外补一行。

**裁剪（第 4 步）。** 以下几类行会被去掉：

| 去掉的行 | 计数 |
|---|---|
| 复位有效，或复位本身是 X | `reset` |
| 某个顶层数据输入是 X | `x`；这一行同时把用例切开 |
| 复位撤销后，有复位值的寄存器还是 X 的前几行 | `init` |
| 第一次复位之前（只在波形里确实出现过复位时才算） | `before_reset` |
| 不足 `n3_min_case_cycles` 行的片段 | `short` |

**用例。** 一个用例是一份波形里两次复位之间的一段。每个用例还记下它之前那段复位期间各顶层输入的取值（`detail.reset_inputs`），供 N3a 挖"复位期间固定值"。回归测试在两个测试之间复位，就切成两个用例；一次随机仿真、一条形式轨迹各是一个用例。内容完全相同的用例只保留一个，比如 testbench 的两次运行都跑了同一个测试。

**切分（第 5 步）。** 每个用例整体进入一个集合，不按时间切。

- 规则：`tagged_hash("n3_split", {seed, 用例 hash}) % 100 < n3_val_percent`（默认 30）的进入 S_val，其余进入 S_mine
- 同样的用例在任何一次运行里都分到同一个集合
- 有两个以上用例时，保证两个集合都不空；只有一个用例时全部进 S_mine，并给出警告 `N3_SINGLE_CASE`

## 覆盖与质量

| 项目 | 目标 | 说明 |
|---|---|---|
| 分支 | 每条带赋值的控制路径（与 N2b 的 `dead.branch` 相同，另加 case 的 default 分支） | 在每一拍上对 N1 的条件表达式树求值，按 SV 的上下文位宽回绕 |
| 状态 | N2 识别出的每个状态机的每个状态 | 同时报告状态机取到的未知编码 |
| 状态迁移 | N2 迁移图里的迁移（不含自环和隐式保持） | 看相邻两拍 |
| 信号翻转 | 每个采样信号的每一位，0→1 和 1→0 都出现过 | 不含时钟和复位 |

条件里用到的信号如果不在波形里，这条分支记为"不可观测"，不算缺口。用户只 dump 了部分信号时会出现这种情况。

**质量（第 7 步）：**

- 有状态机时看状态覆盖，没有时看分支覆盖
- 低于 `n3_min_state_coverage`（默认 0.8）时给出警告 `N3_LOW_COVERAGE`，建议补激励或启用 `--explore`；如果已经做过形式探索，则建议补定向激励或 assume

## 哈希、落库与复用

- **input_hash** 由以下各项求哈希得到（`tagged_hash("n3_input", …)`）：
  - N2 的 input_hash、build_hash、env_hash（含 Icarus、Verilator、yosys、sby、pywellen 版本）
  - `assumes`
  - 波形文件的内容 hash
  - testbench 配置及其文件的内容 hash
  - N3 参数、`run.seed`、命令行开关、`N3_VERSION`
  - 波形和 testbench 只作为 N3 的输入，不进 build_hash，所以改 testbench 不会让 N1、N2 重算
- **用例 hash** 由采样表求哈希得到（`tagged_hash("n3_case", 采样表)`）。**traces_hash** 由全部用例的 id、hash、集合、合法性求哈希得到。实测同一输入重新仿真，traces_hash 完全一致，形式探索的轨迹也一样
- **表：**
  - `n3_run`：主键 input_hash，记录 traces_hash、来源、探索结果、覆盖、质量
  - `n3_case`：每个用例的 id、hash、类型、来源、合法性、集合、周期数
  - 采样表按内容寻址存放在 `traces/<case hash>.json.gz`，同样的用例只存一份
- **复用：** 同一 input_hash 再跑时直接读已存的轨迹，不重新仿真，结果标 `cached`。加 `--fresh` 则强制重跑

## 参数（`run.params`）

| 参数 | 默认 | 含义 |
|---|---|---|
| `n3_random_runs` / `n3_random_cycles` | 8 / 200 | 随机仿真的次数和每次的拍数 |
| `n3_idle_cycles` / `n3_max_toggle_cases` | 32 / 32 | 保守激励的拍数和单点翻转的最多位数 |
| `n3_val_percent` | 30 | 进入 S_val 的用例比例 |
| `n3_min_state_coverage` | 0.8 | 质量阈值 |
| `n3_min_case_cycles` | 2 | 用例的最少行数 |
| `n3_explore_depth` / `n3_explore_timeout` / `n3_explore_max` | 20 / 120 / 64 | 形式探索的深度、超时和目标数上限 |
| `n3_simulator` | auto | 生成激励用的仿真器 |

## 验收

规格没有给 N3 定量指标。测试（`tests/test_n3.py`，样例在 `tests/golden/n3/`）检查以下几点：

- **采样语义。** fifo 的随机轨迹里，每一行都满足 `count[i+1] = count[i] + (push && !full) - (pop && !empty)`
- **合法性。**
  - 随机轨迹里没有一拍违反假设 `full |-> !push`
  - 没有假设时只有空闲和单点翻转两类用例，全部标 `unknown`，也不做形式探索
- **形式探索。** 在 `lock.sv` 上：
  - 随机仿真碰不到 `key == 16'hBEEF` 这个分支，形式探索能到达
  - 假设禁止 `req_a && req_b`，ORPHAN 状态被证明不可达
  - 最终分支、状态、迁移覆盖都是 100%
- **用户来源。**
  - testbench 按复位切成用例，重复的用例被去掉
  - 手写的 VCD 检查了转义名、generate 块名，以及复位、X 输入、第二次复位处的裁剪和切分
  - 内置 VCD 读取器与 wellen 的结果逐个变化一致
- **切分。** 同一个用例不会同时出现在两个集合里，同样的输入切分结果相同
- **存储。** 落库、复用、重新仿真后哈希一致；种子是输入，改种子会改变 input_hash 和 traces_hash

## 待定

- 多时钟设计只按第一个时钟采样，其余时钟域的值是近似。真正的多时钟采样要等 N4 确定需要什么样的数据。
- 生成的 testbench 驱动不了接口端口和非压缩数组端口，遇到时给出警告 `N3_AUTO_UNSUPPORTED`，此时只能用用户波形或 testbench。
- 随机激励是均匀分布，没有按协议加偏置（比如让 valid 多保持几拍）。N3a 挖出协议假设后，可以把这些假设同时用作约束和偏置。
- 存储器不采样；N4 如果需要存储器内容，要另外处理。
- N2 角色表里的 `trace` 证据（规格 N2 第 7 步写的"N3 之后补充"）这次没有回填，留到 N4 挖掘时一起做。
- PicoRV32、Ibex 还没跑。
